部署与使用文档

从一台新服务器开始，到 Telegram 登录、下载配置与长期维护。本文档覆盖 Docker、原生运行、反向代理、备份和安全基线。

推荐路径

大多数用户应选择 Docker Compose。它已固定 data 与 downloads 两个持久化目录，并能避免升级时丢失登录会话与下载文件。

QUICK START

5 分钟快速开始

安装 Docker 后，克隆官方仓库并启动服务。首次配置和 Telegram 登录都在浏览器内完成。

  1. 01
    克隆仓库

    确保当前目录为空，或选择一个新的部署目录。

  2. 02
    启动 Compose

    首次启动会自动构建镜像；后续启动无需再次构建。

  3. 03
    打开工作台

    访问 http://服务器IP:8000/dashboard，按向导完成配置。

bash · quick start
git clone https://github.com/cvpia/telegram-media-downloader-web.git
cd telegram-media-downloader-web
docker compose up -d --build
REQUIREMENTS

环境要求

DockerEngine 24+

需要 Compose v2，建议使用官方 Docker 安装方式。

系统资源2 CPU / 1 GB

建议至少 2 GB 可用磁盘；媒体文件较大时应预留更多空间。

系统Linux / Windows

也可在支持 Docker 的 NAS 或其他宿主机上运行。

端口 默认映射宿主机的 8000 端口。若被占用，请修改 docker-compose.yml 的端口映射。
RECOMMENDED

Docker Compose 部署

官方 docker-compose.yml 会设置持久化挂载，并在容器内未挂载 /data 或 /downloads 时拒绝启动，防止配置落进临时容器层。

bash · compose
git clone https://github.com/cvpia/telegram-media-downloader-web.git
cd telegram-media-downloader-web
docker compose up -d --build
docker compose ps

启动后检查

健康检查通过后，访问 /health 应返回 {"status":"ok"}。然后打开 /dashboard 完成配置。

查看日志

使用 docker compose logs -f --tail=100 查看启动和 Telegram 连接日志，不要公开分享包含登录信息的完整日志。

PREBUILT IMAGE

使用预构建镜像

如果不希望本地构建，可直接拉取 Docker Hub 镜像。数据库、密钥和会话仍必须通过卷挂载持久化。

bash · docker hub
docker pull xxoo520zls/telegram-media-downloader-web:3.13.1
docker compose up -d

Compose 配置中的 image 字段会同步标记本地构建结果，因此源码构建和镜像部署可以共用同一份配置。

ALTERNATIVE

Python 原生运行

需要 Python 3.12 或 3.13。TgCrypto 可提升 Telegram 媒体传输效率；Windows 与 Linux 均支持。

bash · native
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
PRODUCTION

反向代理与 HTTPS

应用默认使用 HTTP。把服务暴露到公网前，应在 Nginx、Caddy 或云负载均衡层启用 HTTPS，并限制后台访问来源。

nginx · server block
server {
    listen 443 ssl http2;
    server_name media.example.com;

    client_max_body_size 1024m;
    proxy_read_timeout 3600s;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
SSE 与长时间请求

下载监控依赖 Server-Sent Events。代理层请关闭响应缓冲并设置足够长的读取超时。

FIRST RUN

首次配置

  1. 01
    网络代理

    按实际网络环境配置 HTTP 或 SOCKS 代理，并通过连接测试后再继续。

  2. 02
    管理员密码

    使用强密码保护管理后台。密码以 scrypt 哈希保存。

  3. 03
    Telegram API

    填写 API ID 与 API Hash。敏感信息会使用本地密钥加密。

  4. 04
    Telegram 登录

    输入手机号、验证码和两步验证密码，完成用户会话登录。

  5. 05
    下载偏好

    设置媒体类型、目录结构、文件名模板和最大并发数。

DATA

数据持久化

以下两个目录必须保留。重建容器时如果未挂载它们，配置、密钥、Telegram 会话和媒体文件都可能丢失。

./data应用数据

SQLite、加密密钥、Telegram 会话、日志和数据库备份。

./downloads媒体文件

按频道、日期和媒体类型组织的下载内容。

./data/.secret.key加密密钥

丢失后无法解密已保存的 API Hash、Bot Token 和代理密码。

MAINTENANCE

更新与回滚

bash · update
git pull
docker compose pull
docker compose up -d
docker compose logs -f --tail=100

不要在更新前执行 docker compose down -v。该命令会删除数据卷，且可能造成不可恢复的数据丢失。

SECURITY

安全与备份

定期备份

备份整个 data/ 目录，尤其是 app.db、.secret.key 与 Telegram 会话文件。先停止服务再复制可避免数据库写入竞争。

最小暴露面

只开放反向代理端口；不要将 Telegram 会话文件、API Hash、Bot Token 或日志提交到 Git 仓库。

bash · backup
docker compose stop
tar -czf telegram-media-backup-$(date +%F).tar.gz data downloads
docker compose start
TROUBLESHOOTING

故障排查

容器启动后立即退出

检查 docker compose logs。Compose 在 /data 或 /downloads 未正确挂载时会主动拒绝启动。

无法连接 Telegram

先确认宿主机的网络与代理设置，再回到配置向导重新测试代理。不要直接修改数据库中的加密凭据。

下载任务频繁失败

检查磁盘空间、Telegram 账号状态和日志中的重试原因。系统会指数退避并在队列结束后优先重试失败资源。

反向代理后 SSE 不再更新

关闭代理响应缓冲，延长读取超时，并确保 X-Accel-Buffering: no 等流式响应头未被覆盖。
